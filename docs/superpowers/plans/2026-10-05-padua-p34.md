# Padua Phase 3 (Interviews) und Phase 4 (Frame) live-reif — Implementierungsplan

> **Für agentische Ausführung:** PFLICHT-Unterskill
> `superpowers:subagent-driven-development` (empfohlen) oder
> `superpowers:executing-plans`, Task für Task. Schritte haben Checkboxen
> (`- [ ]`). TDD je Code-Task: erst der rote Test, dann der Code.

**Ziel:** Phase 3 und Phase 4 der Padua-Gruppen live-reif machen, mit derselben
Methode wie Phase 1–2 heute: automatische Prüfungen (Browsersimulation mit
deterministischen Invarianten + Richter, Prompt-Check) finden Befunde,
Klasse‑A-Befunde werden mit TDD behoben, Klasse‑B-Entscheidungen werden für
Birk gesammelt.

**Karten:** `t_92f99911` (Flow-Audit P3–4, Gesamtauftrag), `t_cf87ee0a`
(Brainstorm = ein Toggle je Gedankenbogen, Stopp löst CoThinker aus, keine
Pausenerkennung — Birks Entscheidung, umsetzen), `t_a8129d7f`
(Brainstorm-UX), `t_3f8bbbc3` (VAD-Pre-Roll — nur wenn billig), `t_c5cc5a62`
(CoThinker inhaltlich prüfen — als Prüfung in der Simulation).

**Architektur:** Ein Bugfix im Brainstorm-JS (T1), dann Werkzeug (T2: Stationen
`p34`, Invarianten, Startzustand Phase 3; T3: Prompt-Check P3/P4), dann der
Brainstorm-Umbau serverseitig (T4) und im Browser (T5), damit der Lauf das neue
Verhalten prüft. Danach ein Simulationslauf + Prompt-Check (T6), höchstens drei
Fix-Runden (T7), Bericht + volle Suite (T8).

**Tech:** Python 3.11, SQLite, Standardbibliothek-Web (`web_chat.py` mit
eingebettetem JS), Playwright für e2e und Simulation, espeak-ng für
Simulations-Audio.
